# 공개 소개 페이지 (과제 8 카드 1)

첫 화면 `/`는 로그인 없이 누구나 볼 수 있는 **이 웹 서비스(Plan-Do-See Diary)의 소개 페이지**입니다.
만든 사람을 소개하는 페이지가 아닙니다. (사용자가 "소개는 이 웹페이지의 소개이고 나를 소개하는 게 아니다"라고 정정함, 2026-10-30)

## 무엇이 들어 있나

| 구역 | 내용 |
|---|---|
| 맨 위 파란 띠 | "공개 영역" 표시와 로그인·비공개 영역 링크. 공개 영역과 비공개 영역(`/private`)을 구분하는 표지 |
| 머리글 | 서비스 이름, 로그인·가입하기 버튼 |
| 히어로 | "계획하고, 실행하고, 결과를 돌아보는 다이어리"와 한 단락 설명, 가입·로그인 버튼 |
| 이렇게 씁니다 | Plan · Do · See 3단계 카드 (각 3줄) |
| 공개된 곳과 로그인해야 열리는 곳 | 이 페이지는 공개이고, 계획과 비공개 영역은 로그인이 필요하다는 안내. 지금의 로그인 방식이 이메일·비밀번호라는 점도 적음 |
| 바닥글 | 서비스 이름, © 2026 |

## 문구를 어디서 가져왔나 (실제 기능만 적었다)

| 소개 문구 | 근거 |
|---|---|
| 기간·우선순위·성공 기준·예상 시간, 계획 수정 시 이전 내용 보존 | `plans` 표의 열(실제 DB 조회), `README.md`의 API 표(`PATCH`는 수정 전 내용을 revision으로 보존) |
| 할 일의 마감일·태그·예상 시간 | `todos` 표의 열(실제 DB 조회) |
| 실행 시작·일시정지·재개·종료, 일시정지 시간 제외 | `app/plans/[plan_id]/execution-controls.tsx`, `README.md` |
| 시작하면 진행 중, 종료하면 완료 | `execution-controls.tsx`("실행을 종료하면 이 할 일이 완료로 바뀝니다"), `db/migrations/20261021030000_link_todo_status_to_execution.sql` |
| 예상 시간 대비 실제 시간, 할 일별 표 | `app/plans/[plan_id]/summary-section.tsx` |
| 계획별·전체 CSV 내려받기 | `app/export-links.tsx`, `app/plans-board.tsx`, `app/plans/[plan_id]/summary-section.tsx` |
| 이메일 가입·확인 메일·로그인, 로그인 방식 | `docs/auth.md`, `app/auth/actions.ts` |

아직 없는 기능(패스키 등)은 적지 않았습니다.

## 넣지 않은 것

개인 이름·연락처·이메일·계정 식별 정보, 개인 프로젝트·성과·외부 링크, 비공개 항목. `app/page.tsx`는 로그인 확인도 DB 조회도 하지 않는 정적 페이지입니다.

## 이전에 있던 개인 포트폴리오 소개 파일

작업 중 `/`를 개인 포트폴리오(출처 `github.com/arnixs115/my_portpolio`)로 만든 버전이 작업 폴더에 들어와 있었습니다. 소개의 대상이 웹 서비스라는 정정에 따라 `/`에서 쓰지 않습니다.
`app/_intro/`, `lib/intro/portfolio-data.ts`는 **지우지 않고 그대로 남겨 두었지만 어디에서도 import되지 않아** 화면과 브라우저용 번들에 나오지 않습니다. 필요 없으면 두 폴더를 지워도 다른 파일에 영향이 없습니다. (직접 확인: 두 폴더 밖에서 이들을 가져오는 코드 없음)

## 확인한 것과 못 한 것

확인 방법과 결과는 [`private-area.md`](private-area.md)의 "확인한 것"에 있습니다. 이 페이지에 대해 특히:

- `node scripts/verify-intro.mjs`: 비로그인 `/`가 200이고 소개 문구 21개가 HTML에 있으며, 비공개 항목·이메일 형태 문자열이 없고, `/private`·`/plans`는 로그인 화면으로 이동하고, 비공개 API는 401이다.
- 브라우저(헤드리스 Chromium)로 본 것: 밝은·어두운 테마와 390px 모바일에서 레이아웃, 가로 넘침 없음, 링크 이동.
- **못 본 것:** 사람이 실제 브라우저로 보는 확인, Vercel 배포본, 다른 브라우저·기기.

## 직접 확인하는 방법

1. 시크릿 창에서 배포 주소의 `/`를 엽니다 → 로그인 화면으로 이동하지 않고 이 소개가 보여야 합니다. 맨 위에 파란 "공개 영역" 띠가 있어야 합니다.
2. "가입하기", "로그인" 버튼이 각각 `/signup`, `/login`으로 가는지 확인합니다.
3. 페이지 소스 보기에 개인 이름이나 비공개 항목("별빛 일지" 등)이 없어야 합니다.
4. 로그인한 뒤에도 `/`는 소개 페이지이고, 헤더의 "소개 페이지" 버튼이 `/`로, "계획 목록으로"가 `/plans`로 가야 합니다.
5. `node scripts/verify-intro.mjs https://<배포 주소>`
